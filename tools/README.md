# Tools

Run all of these from the repository root, next to `build.asm` and `fe4.sfc`.

## Build helpers

| Tool | Purpose |
|---|---|
| `c2a.py`, `process_dialogue.py` | Convert CSV tables and dialogue text to assembly (download them; see the main README). |
| `FE4c2a.py` | Converts the character and item data tables. |
| `gen_offsets.py` | Auto-generates the 13 1-to-1 offset tables in `data/offset/*.csv.asm` from their source CSVs, `ClassMapSpriteAssignment.asm`, and `text/menutext/*.asm`. `build.sh` runs it. |
| `checksums.py` | Verifies or updates FE4's internal code checksums (`$80`/`$87`/`$88`/`$8F`) and SNES header checksum. `build.sh` runs it (`--verify` on build, `--update` on `mod`). |
| `check_paths.py` | Checks that every included file exists with exactly the spelling used. `build.sh` runs it. |
| `merge_bank.py BANK` | Removes the pins (`* =` and `.logical`) of every block in a bank of `build.asm` that starts exactly where the block before it ends, so the bank's code flows as one block. Lists the pins that stay and why (a gap not built from source, or other code between them). A free run of `$00`/`$FF` from the merged block to the bank end becomes `.fill <bank end> - *`, so the block can grow into it, and old `; 84/XXXX` end comments in the block are dropped. `--dry-run` only lists. The output does not change; run `./build.sh`. |
| `pad_test.py` | The padding test, run as `./build.sh pad SECTION N`: builds `FE4Padded.sfc` with N bytes of `$EA` (NOP) inserted at the start of SECTION in a temporary copy, and checks that the block (the sections between that `* =` and its `.here` in `build.asm`) moved cleanly: room to grow after it (or a `.fill` to the bank end that absorbs the bytes), every label in it moved by N and none outside it, which bytes elsewhere changed (references the assembler updated), calls into the block (`jsl`/`jml`, and `jsr`/`jmp` from the same bank) from bytes not built from source, which cannot move with it (a problem if `fe4.cdl` shows they ran; matches in the lower half of a bank or past bank `$9F`, where the game keeps only data, are listed apart), long pointers into the block (low, high, bank) in unbuilt bytes in the code banks' upper halves (a problem unless listed in `NOT_POINTERS`, the matches checked by hand and found to be chance), six-digit numbers in the source that are addresses in the block (`jml $84F889`: built, but they do not move), and nothing changed in the code the game checksums. It fixes the header checksum. Hidden addresses (numbers that are really addresses) only show when you run the ROM: `open -a Mesen FE4Padded.sfc`. |

## Bringing new code into the build

These tools work on a *routines file*: disassembled routines in the usual style, each starting with a top-level label and its address:

```
      rsAIEngineSetupCycle ; 86/9D75

        .al
        .autsiz
        .databank ?

        lda wActiveFactionSlot,b
        ...
```

A label with a directive on the same line counts too (`      aTable .word 1, 2 ; 85/8000`). Everything from one routine's label up to the next label belongs to that routine and moves with it, so keep unrelated notes out of the space after the last routine in a file.

The files in `wip/` are routines files. Each tool assembles the file in a temporary copy of the repository, so your working tree is only changed where a tool says so.

| Tool | Purpose |
|---|---|
| `disasm.py START [END]` | Disassembles code from the ROM into a routine in the project's style, following register widths and the data bank and using existing names. Where `fe4.cdl` shows an instruction ran, it takes the widths from the log, never writes those bytes as data, and labels the return point of `pea #X-1` (`--no-log` to turn this off). Without END it stops where the routine ends. `--selftest` checks it against every routine already in the build. |
| `trace.py` | Follows calls, jumps, engine definitions, proc scripts and pointer tables from every built routine into code that is not built yet, and disassembles what it finds. With `fe4.cdl` it also follows `jsr (table,x)`/`jmp (table,x)` through the entries the log shows used. `--from-log` also starts from every entry point of executed code in the log. A routine found inside another (a second table entry into the same code) is written as a local label of the outer one (`outer._XXXX`). Tables that built code jumps through are followed even when none of their entries is built yet; words below `$8000` and `$FFFF` in a table are unused slots. `--list` shows each routine with a caller and warnings; `--write FILE` writes them as a routines file. |
| `proc_scripts.py FILE` | Writes proc scripts and unlabelled proc headers that are not built yet as a routines file, using the `PROC_*` macros. `procs.py` holds the script format it and `trace.py` use. |
| `event_script.py START END [--movement]` | Decodes an event script (or with `--movement` a movement or scroll script) in the ROM into the event macros of `include/events/`. Reads the command layouts from `Main.h`; jump targets become local labels, pointers labels from `labels.txt`, characters names. Commands the macros cannot express exactly come out as `.byte` with a comment. Check the result by building. |
| `move_sections.py SPEC` | Moves whole sections between engine files (SPEC lines: section name, target file). Cannot change the ROM. |
| `rom_tables.py FILE` | Labels the unbuilt ROM tables that built code reads: writes those with a certain extent to FILE and named the rest weakly in `include/Undisassembled.h`, which is gone now that the build is all source. |
| `sweep.py` | Decodes gaps in the code banks that nothing points to and writes the candidates with enough evidence (`--min-score`, default 3) to a routines file. |
| `cdl.py [CDL]` | Compares a Mesen code/data log (`fe4.cdl`) with the build: executed code that is not built and the raw pointers that lead to it, built code read as tables, built data that is executed, bulk reads of code, and (while it existed) the read extents of the tables in `include/Undisassembled.h`. `--report FILE` writes Markdown (keeping hand-written text above its marker line); `--entries FILE` lists the entry points of unbuilt code with their register widths. |
| `raw_addresses.py` | Writes six-digit ROM addresses in `engine/` and `events/` as labels: `tools/raw_addresses.py [--list] [--write]`. A label at the address (global, or `routine._XXXX` for a local one) is used as it is; an instruction with no label gets a local label `_XXXX`, since it is an entry point; an address inside built data or inside an instruction becomes the nearest label before it plus N, and an indexed read 1-4 bytes before a data label that label minus N. It works from `labels.txt`, a 64tass listing and the built-bytes map; numbers into unbuilt bytes or the other ROM mirror are left and counted. `--write` builds; running it again finds nothing. |
| `bank_addresses.py` | Lists the raw four-digit ROM addresses the other two tools miss (it changes nothing): `lda $AA2A,b,y` and the like where the data bank is a ROM bank, `ldy #$XXXX` before `jsl rlPushToOAMBuffer` (a sprite array), DMA sources loaded as `lda #$BB00 / sta $43x3 / lda #$XXXX / sta $43x2`, and raw `.word`/`.long` inline arguments after a call. Each line gives the address and the label it falls in. A fixed-source DMA often reads a zero inside a routine: label it `_DMAFillZero` and write `Routine._DMAFillZero+1`. Prints nothing after a clean pass. |
| `code_pointers.py` | Writes raw code pointers stored into the variables the engines jump through (`wVBlankPointer`, `wIRQPointer`, `wMainLoopPointer` and the on-cycle routines of procs, HDMA and active sprites) as `<>label`. The target bank comes from the dispatching code: `$80` for the first three, the header's bank for the rest, settled by the header that runs the storing routine or else confirmed by `fe4.cdl`. It also writes long pointers loaded in two halves (`lda #$8A00 / sta lR18+1` with `lda #$88E0 / sta lR18`) as `` #(`label)<<8 `` and `#<>label` where exactly one label is at the full address, including indexed stores (`sta aTitleTimelineSlots.lRoutine+1,x`) and long stores (`sta @l lMapMenuTilemapRAMEntryPointer+1`). Reports every store it leaves and why; `--write` applies it and clears the "nothing reaches this" comments of the routines that now have a reference. |
| `label_data.py ADDR[=NAME] ...` | Puts a top-level label at an address inside a built `.byte` data block by splitting its row (`aUnknownXXXXXX` or NAME), so that a pointer into the block can become a label (`code_pointers.py --write` then writes it). Local labels inside the block are passed over; an address that has one is reported, to be written `Parent._XXXX` by hand. `--from-code-pointers` takes every "no label at the address" data target from `code_pointers.py`. |
| `ram_lists.py [--write]` | Writes the lists that `rlBattleSceneWriteRAM` reads (a word of address and type, then a byte, word, or AND and OR operands; `$FFFF` ends) as `WRITE_RAM_*` macros (`include/BattleAnimation.h`), the direct page buffers by name. Finds every call whose `lR18` is loaded just before it, as labels or raw halves; rewrites labelled lists in place when their bytes match, and writes unbuilt ones to `wip/ram_lists.asm` for `place_routines.py`. |
| `palette_effects.py [--write]` | Writes the entries `rlBattleSceneStartPaletteEffect` reads (slot, type, first color, count, then by type a long pointer, a byte, or both) as `PALETTE_EFFECT_*` macros (`include/BattleScene.h`). Finds them through `aBattleScenePaletteEffects` and the `lda #<>label` before each call; bytes after an entry stay `.byte` rows; lists pointers into the ROM with no label (give them one with `label_data.py`). Was run once over all 204 entries. |
| `title_timeline.py ADDR ... \| --write` | Prints the title screen's timelines as `TITLE_TIMELINE_*` macros (`include/TitleScreen.h`); `--write` was used once to replace the `.byte` rows at `$97/EC63`-`F19B`. |
| `decompress.py` | The game's decompressor (`rlDecompressor`) in Python: `tools/decompress.py ADDR ...` prints each stream's compressed and decompressed length and where it ends (`--hex`, `--out FILE` for the output); as a module, `decompress(rom, addr)` returns `(data, end)`; `linear=True` reads the way the sound loader's entry `rlDecompressLinear` does (banks run on from `$FFFF` to `$0000`). Use it to measure compressed blocks when carving them into labelled slices. `--self-test` checks it against the streams in `gfx/` and the portraits. |
| `carve.py` | Carves what a pointer table points at into labelled source: `tools/carve.py TABLE --type TYPE --name NAME [--dir DIR] [--end ADDR] [--write]`. TABLE is a label followed by `.long` lines, or a pointer CSV. TYPE says how long each target is: `dialogue` (to its EOF, written as text files under `text/dialogue/DIR`), `compressed` (measured by `decompress.py`), `fixed:N`, or `next` (to the next target); the last three are written as `.text ROM[...]` slices, split where they cross a bank half. `--type block` takes `ADDR:SIZE` instead of a table and carves one region, such as a tile sheet code indexes by offset. Gaps between targets are decoded as more of the same where they fit exactly (named `NAMEUnknownADDR`), else become `aUnknownADDR` slices. Without `--write` it reports the runs and any problems (a target that runs into the next, overlaps with source); with it, it writes the blocks into `build.asm`, rewrites the table with the labels, replaces raw six-digit numbers in the source that point into the blocks or the table (as `label+N`), and builds. |
| `dialogue.py` | Decodes dialogue in the ROM into the text format `process_dialogue.py` reads, so that it converts back to the same bytes: `tools/dialogue.py ADDR ...`; as a module, `Decoder().decode(rom, addr[, end])`. It leaves out the font page switches the encoder puts back by itself and writes the others as `{DIALOGUE_FONT_n}`, and writes arguments as the existing files do (portraits, characters, labels for pointers). `--self-test` decodes all the dialogue in the build from the ROM and rebuilds with it. |
| `item_icons.py` | Builds [data/item/ItemIconOffsets.asm](../data/item/ItemIconOffsets.asm) from [gfx/icons/ItemIcons.json](../gfx/icons/ItemIcons.json) and `gfx/icons/ItemIcons.4bpp.png` (`build`, run by `build.sh` and `build.bat`; `clean`), exports/packs named `16×16` indexed PNGs (`unpack-icons`/`pack-icons`), renders labeled `sheet.png` and `items.png` previews (`preview OUT_DIR`), and adds new icon slots (`add NAME [PNG] [--item ITEM]`). `--self-test` verifies ROM match, round-trip, `add`, and validation. |
| `gfx.py` | Converts 4bpp and 2bpp tile graphics to and from indexed PNG (the depth comes from the file name, `.2bpp` or `.4bpp`): `png2bpp IN.4bpp.png OUT.4bpp` (what `build.sh` runs for every `gfx/**/NAME.4bpp.png` and `NAME.2bpp.png`), `bpp2png IN.4bpp OUT.png --palette FILE|ADDR|grey [--width TILES]` to extract, and `lz IN.4bpp ORIGINAL.4bpp.comp OUT.4bpp.lz`, which copies the committed original stream while it still decompresses to IN and otherwise compresses IN with `compress.py` (so unedited graphics build byte-identical); `build.sh` runs it for `NAME.4bpp` and for `NAME.bin` (decompressed tilemaps and the like, beside `NAME.bin.comp`), dropping the blank tiles that fill out a PNG's last row. A pixel's palette index is its colour number, so edits keep exact colours as long as the PNG stays indexed. `--self-test` round-trips every PNG in `gfx/`. Needs Pillow. |
| `gfx_blocks.py` | Turns labelled slices of uncompressed tile graphics (`carve.py --type block`) into indexed PNGs: `tools/gfx_blocks.py LIST [--write]`, LIST holding `LABEL NEWLABEL gfx/DIR/NAME.4bpp.png PALETTE [WIDTH]` (or `.2bpp.png`). PALETTE only colours the PNG (`grey`, an address, `LABEL+N`). Checks each PNG converts back to the slice's bytes, replaces the slice with `NEWLABEL .binary "gfx/DIR/NAME.4bpp"`, renames the label everywhere and builds. The default width is the largest up to 16 that divides the tile count, so no filler tiles reach the build. Settle the depth from the code first (`gfx/ui/README.md` shows how). |
| `compress.py` | A compressor for `rlDecompressor`: `tools/compress.py IN OUT`, or `compress(data)`. It finds the smallest encoding (an optimal parse), about 97% of the size of the game's own streams; its bytes differ from the ROM's, which is why the build keeps original streams for unedited graphics. Slow on large graphics with long runs of zeros (seconds per file); `--self-test` checks it on the streams in `gfx/`. |
| `stream_layout.py` | Lays out compressed streams across the lower halves of banks: `tools/stream_layout.py LIST.streams OUT.asm`. LIST gives the region (`start`, `end`) and the streams in order (`LABEL NAME`, for `NAME.4bpp.lz`, `NAME.2bpp.lz`, or `NAME.bin.lz` beside it); OUT gets one placement block per bank half, splitting a stream that reaches `$8000` and continuing it at `$0000` of the next bank, as the decompressor reads it. `build.sh` runs it for every `gfx/**/*.streams`; it fails if the streams outgrow the region. |
| `find_streams.py` | Finds compressed streams and carves them into `gfx/build/ADDR/`: `tools/find_streams.py [--table LABEL ...] [--write]`. Starting points are the sources loaded before calls of the decompression routines, the `.structDecompressionDMAEntry` entries, the values of the pointer tables named with `--table`, and the streams already listed; neighbouring starts form a region when the streams in between decode end to end onto the next one, and a region runs on after its last start while the bytes decode to whole tiles. `--write` writes each region as `NAME.comp` files and a `.streams` list (built by `stream_layout.py`), removes the `ROM[...]` slices they replace, writes the numbers and two-halves loads in the source that point at a stream as labels, and builds. Unidentified streams are named `gcUnknownADDR`. A region whose streams are exactly what its `.streams` file already lists is left untouched (names, notes and PNGs), so running it again changes nothing. |
| `name_streams.py` | Renames compressed streams: `tools/name_streams.py FILE [--write]`, FILE holding `OLD NEW` lines. Renames the label everywhere in the source, the stream's `.streams` line and its files (`.comp`, `.4bpp.comp`, `.4bpp.png`, `.2bpp.comp`, `.2bpp.png`, `.bin.comp`, `.bin`, with `git mv`); `#:` lines above a rename become comments above its `.streams` entry. Refuses a NEW name already in use. |
| `carve_palettes.py` | Carves palettes into labelled `.word` data: `tools/carve_palettes.py LIST FILE [--write]`, LIST holding `LABEL ADDR SIZE` lines. Palettes that follow one another share a section; it places the sections in `build.asm`, rewrites raw numbers pointing into a palette as `LABEL+N` and builds. Refuses palettes that overlap built bytes. |
| `unpack_streams.py` | Turns carved streams into editable files: `tools/unpack_streams.py LIST [--write]`, LIST holding `LABEL 4bpp PALETTE [WIDTH]` (4bpp tiles, as `NAME.4bpp.png`), `LABEL 2bpp PALETTE [WIDTH]` (2bpp tiles, as `NAME.2bpp.png`), or `LABEL bin` (a tilemap or other data, decompressed, as `NAME.bin`). `LABEL colours PALETTE` gives an unpacked PNG other colours, checking its pixels still convert to the same bytes. PALETTE only colours the PNG: an address, `LABEL+N`, `stream:LABEL+N` or `grey`; `@1` at the end takes the colours from colour 1 on, as sprite palettes are copied, with colour 0 black. |
| `backgrounds.py` | Renders the dialogue backgrounds (picture with its foreground), the battle backgrounds and the map battle magic layers from the built ROM, as previews: `tools/backgrounds.py OUT_DIR [--scale N]`. `--self-test` edits `gfx/scenes/battle/Plains.png` in a copy (a copied cell, and a pixel needing a new tile in the full sheet), builds with `./build.sh mod`, fails unless the build succeeds and Plains' tiles and tilemap changed, and checks the ROM decompresses to the edits while every other entry stays the same. |
| `scene_pack.py` | Builds the scene, background and UI layout layers (`gfx/scenes/**/*.scene.json`, `gfx/ui/layouts/*.scene.json`) into `.4bpp`/`.2bpp` sheets and `.bin` tilemaps (`build`, run by `build.sh` and `build.bat`; `clean`). ### Typical workflow

0. For code that has never been disassembled, `tools/disasm.py START > wip/File.asm` (add `--m8`/`--x8` if the routine starts with 8-bit registers). Its output normally matches the ROM straight away; what it needs is names and comments.
1. `tools/test_routines.py wip/File.asm` to see what fails.
2. Fix assembly errors. `tools/fix_addressing.py wip/File.asm` handles the data bank ones; the rest are usually names that do not exist or point at the wrong thing.
3. `tools/fix_addressing.py wip/File.asm` again once it assembles, then `tools/test_routines.py wip/File.asm --long-branch --diagnose` and `tools/show_lines.py` for what is left. The ROM decides: if the source says `trb` and the ROM has `tsb`, the source is wrong.
4. Write a SPEC grouping the matching routines by game system, then run `tools/place_routines.py wip/File.asm SPEC --remove`.
5. Describe any new files (they start with a TODO line), run `./build.sh`, and commit.

### 64tass details that matter here

- Register widths (`.al`/`.as`, `.xl`/`.xs`) carry over in the order 64tass reads the source, not in ROM order. That is why every section states its starting widths; the tools measure them for you.
- `addr,b` means "absolute addressing, with a 16-bit operand". It does not subtract the data bank, so `$7F4418,b` never assembles. Declare `.databank $7F` instead and write the address without `,b`.
- `@l addr` forces long addressing.
- A label declared as a list (`.brept`) stands for every entry: `lda #<>list` silently emits one instruction per entry. Write `list[0]` for the base address. This caused several mismatches in the wip code (`aAIUnitList`, `aMovingMapSpriteData`, `aSave.aFactionEntryOffsets`).
- In a `.brept` list of structs, use `.dstruct structName` (not the `.structName` shorthand) so that `list[0].field` works.
- A struct macro given `None` for a field emits nothing for it, and `.structX` calls with missing arguments can emit nothing at all without an error. If a routines file reports "no bytes emitted" for data, check those first.
