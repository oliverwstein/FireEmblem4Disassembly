## [data_window.asm](../../../engine/menus/data_window.asm)

The data window: map menu option データ (Data). Shows the chapter, its goal and the turn, and lists the armies on the map with each one's leader, relation to the player and units alive; X shows an army's details: its home castle and its leader's portrait, map sprite, level, HP and attack. Opened by rsDataWindowOpen, then run by game state routines $2F (rlDataWindowRender), $30 (rlDataWindowShow) and $31 (rlDataWindowRunStep), with wGameStateStep as the step. Code and data in banks $80 ($80/D90C-DFD3) and $8B ($8B/CF0A-D794); its variables are at $7F8183 (include/WRAM.h).

## [unit_window.asm](../../../engine/menus/unit_window.asm)

The unit window: the sortable list of units opened from the map menu, with pages, sort orders (by stat, weapon rank, skill...), unit swapping, item and weapon rank icons, map sprites and its own HDMA effects. Code in banks $80 and $8B.  rsUnitWindowOpen sets it up as a main loop routine; then game state routines $20 (rlUnitWindowHandleInput), $21 (rlUnitWindowShow) and $22 (rlUnitWindowRunPageTurnInput) run it, with wGameStateStep as the page (0-5). Its variables are at $7F82C7-$7F8438 (include/WRAM.h); other screens reuse that RAM, such as the item, skill and data windows (item_window.asm, skill_window.asm, data_window.asm).  FE5 kept this code, and the FE5 disassembly (github.com/ZaneAvernathy/FireEmblem5) names it UnitWindowFE4...; the routines named here were matched with it by their code. Its descriptions of the FE4 behaviour are a good guide to the routines still unnamed. rlAddToUnitJoinOrder and rlRemoveFromUnitJoinOrder sit in the middle of this code but are in engine/units/join_order.asm.

97 named, 68 `Unknown`.
