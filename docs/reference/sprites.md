# Sprites

Everything on the screen that is not a background layer goes through one 544-byte copy of OAM in RAM. Routines push sprites into it during the frame, and VBlank sends it to the hardware ([frame.md](frame.md)). This page covers that buffer and the routines that fill it, the per-band quota and flicker used for the map's units, and the active sprite engine: 16 scripted, animated sprites with their own frame step and script commands. The code is in `engine/core/display/` (banks `$80` and `$81`).

The map's units and cursor are not active sprites; the map's VBlank routine draws them directly ([map.md](map.md)). The battle scene has its own animation slots ([battle_scene.md](battle_scene.md)).

Per-routine details: [routines/core.md](routines/core.md) (generated by `tools/reference.py`).

## The sprite buffer

`aSpriteBuffer` holds the 128 OAM entries (X, Y, tile, attributes) and `aSpriteExtBuffer` the 32 bytes of extra bits (bit 8 of X and the size of each sprite). `wNextFreeSpriteOffset` is the next free entry, in bytes.

**A frame of sprites.** Each frame:

1. VBlank sends the buffer (`rlDMAPaletteAndOAMBuffer`) and clears the extra bits (`rlClearSpriteExtBuffer`);
2. the game state routines and the engines push sprites from offset 0 up;
3. at the end of the VBlank routine, `rlHideSprites` moves every entry from `wNextFreeSpriteOffset` to the end to Y = 240, below the screen, and sets the offset back to 0.

Sprites pushed earlier get lower OAM numbers, and so are drawn in front of later ones. In `rsMapVBlank` the order is: the game state routines, the per-frame engines (active sprites), the moving unit (`rlDrawMovingUnitSprite`), the standing units (`rlDrawDeployedUnitMapSprites`).

`rlHideSprites` hides with an unrolled run of 64 `stx` instructions (one per entry's Y byte, with the direct page set to the buffer's first or second half) and jumps into it at `wNextFreeSpriteOffset`, so it runs one store per unused entry. `rlPushToOAMBuffer` sets the extra bits through two tables indexed by the buffer offset: `aOAMSizeBitTable` (the ext byte's address and the size mask) and `aOAMUpperXBitTable` (the X bit 8 mask). The offset wraps at 512 bytes: a 129th sprite overwrites the first, and after exactly 128 the offset is 0 again, so `rlHideSprites` hides them all. Nothing checks the count.

**A sprite array** (`structSpriteArray`) is a word count followed by 5-byte entries (`structSpriteEntry`):

| Bytes | Field |
|---|---|
| 0-1 | X: bits 0-8 the offset (signed, 9 bits), bit 15 a large sprite |
| 2 | Y: a signed offset |
| 3-4 | the OAM tile and attribute word: tile, palette (bits 9-11), priority (12-13), flips (14-15) |

`rlPushToOAMBuffer` draws one array (Y = its address, in the data bank) at `wR0`, `wR1`. Each entry's tile word gets `wR4` added and `wR5` ORed in, so one array serves any VRAM position and palette. It sets the size and X bit 8 in the extra buffer, and puts an entry whose Y lands below the screen (offset + 16 past 255) at Y = 240. `rlPushToOAMBufferTimed` draws only the first `wR2` entries (the world map's markers).

## Map units: band quotas and flicker

The hardware shows at most 34 sprite tiles (8-pixel slices) on a scanline, so 17 sprites 16 pixels wide. The map can have more units on one row than that, so `rlDrawDeployedUnitMapSprites` ([map_sprites.asm](../../engine/map/map_sprites.asm)) pushes them through a quota per 16-line band of the screen:

1. **`rlBeginOAMScanlineFrame`** counts the sprites already in the buffer on each scanline (`rsCountSpritesPerScanline`, 256 bytes at `$7FEC88`): 1 per line for an 8 × 8 sprite, 2 for a 16 × 16, which is two tiles wide.
2. **`rsUpdateOAMBandSpriteLimits`** gives each of the 16 bands a quota of 16 × 16 sprites from its busiest line p: 17 - (p + 1) / 2, or 17 when nothing is in the buffer. A lower quota takes effect at once. A higher one waits until the band's cooldown (`aOAMStripCooldownTimers`) runs out: `wOAMStripCooldownReload` frames, 1 normally and `$30` after `rlEnableOAMScanlineFlicker`, which the map battle calls.
3. **The units.** Each unit's 16 × 16 sprite is added to the list of its band (`$7FEC68`, one column per band, of OAM offsets). A tall unit's top half goes first and is dropped if the band is full; it is marked `$8000`. Then each unit's body (`rlPushToOAMBufferWithScanlineCulling._88D8`): if the band is full, a unit within 16 pixels of the screen's sides is dropped; any other takes the place of the sprite at the band's read cursor, which is moved to Y `$F0`. It does that always when that sprite is a top half, and on odd frames (`wOAMStripFrameCounter`) otherwise.
4. **`rlFinishOAMScanlineFrame`** clears the extra bits of the unused entries.

In a crowded band the units away from the sides take turns, one frame in two; the units near the sides are dropped.

## The active sprite engine

An active sprite is a sprite array with a position, a routine run every frame and a script that changes the array over time. The engine is the second of the per-frame engines ([game_states.md](game_states.md)). Sprites are created by the map battle and its magic effects ([map_battle.md](map_battle.md)), the map actions (village raid, return home, rewards) and two event commands (`CREATE_SPRITE` among them); the castle, the windows, the world map, the epilogue and other screens turn the engine on.

**A definition** (`structActiveSpriteInfo`) is three addresses in the sprite's bank: an init routine, an on-cycle routine and a script.

**The RAM.** `aActiveSpriteSystem` has 16 slots, each field an array of 16 words indexed by slot × 2 (`wOffset` while a sprite runs):

| Field | Meaning |
|---|---|
| `aTypeOffset`, `aBanks` | the definition; 0 means free |
| `aOnCycle`, `aCodeOffset` | the on-cycle routine and where the script continues |
| `aFrameTimer` | frames until the script is read again |
| `aFrameOffset` | the sprite array drawn each frame |
| `aXPosition`, `aYPosition` | the position on the screen |
| `aTileBase`, `aTileBaseHigh` | added to the array's tiles (`wR4`, `wR6` for the renderer) |
| `aPalette` | the palette, ORed into the attributes (`wR5` = it << 9) |
| `aLoopCounter` | the counter of command `$02` |
| `aXSubpixel`, `aYSubpixel`, `aXVelocity`, `aYVelocity` | the fractions (high bytes) and 8.8 velocities `rlMoveActiveSpriteByVelocity` uses |
| `aBody0`-`aBody7` | the user's own: event movers, the map battle and the magic effects each name them after the block in [WRAM.h](../../include/WRAM.h) (`aMoverSpriteStepTimer`, `aMapBattleSpriteSide`, `aMapMagicSpriteTimer` and so on) |

`wFlag` holds the engine's switches ([ActiveSpriteEngine.h](../../include/ActiveSpriteEngine.h)):

| Bit | Set by | Meaning |
|---|---|---|
| `$8000` | `rlEnableActiveSpriteEngine` | the engine runs (the map setup and other screens turn it on) |
| `$4000` | `rlActiveSpriteEngineRenderOnScreenOnly`, the map battle | draw only sprites whose X and Y are 0-255 |
| `$2000` | `rlActiveSpriteEngineSetFlag2000` (the map setup, an event command) | flush the render queue with `rlFlushActiveSpriteOAMQueue2000`, which jumps to the same flush |
| `$0001` | nothing | skip the scripts but still draw |

**Creating.** Each create routine takes the definition in `lR44` and the position in the X and Y registers, and returns carry set when no slot is free:

| Routine | Slot |
|---|---|
| `rlActiveSpriteEngineCreateSpriteHighestSlot` | the highest free (25 calls) |
| `rlActiveSpriteEngineCreateSpriteLowestSlotAbove0` | the lowest free from 1; slot 0 is never taken (20) |
| `rlActiveSpriteEngineCreateSpriteLowestSlot` | the lowest free from 0 (5) |
| `rlCreateActiveSpriteHighestSlotRelative` | the highest free; the definition's addresses count from `lR44` (1) |

`rlCreateActiveSpriteMain` fills the slot: position, routines, a frame timer of 1, the other fields 0, and `aFrameOffset` `$8006` (in bank `$81` that points at an empty array; the first script step sets the real frame before the sprite is drawn). Then it runs the init routine with X = the slot index. `rlActiveSpriteEngineClearAllSprites` frees all 16; `rlActiveSpriteEngineReset` (the init routine) also clears the tile bases, the palette and `wFlag`, so the engine is off.

**The frame.** `rlActiveSpriteEngineMainLoop`, when `wFlag` bit 15 is set:

1. steps each live sprite, slot 15 down to 0: the data bank set to its bank, the on-cycle routine, the frame timer counted down, and at 0 the script;
2. draws every live sprite (or, with `$4000`, the ones on the screen) through `lActiveSpriteRenderer`, with `aFrameOffset` in Y, X and Y in `wR0`/`wR1` (low bytes), the tile bases and the palette;
3. flushes the render queue.

The renderer is `rlPushToOAMBuffer` after a reset. The map battle, the map actions and the cutscenes install `rlPushToOAMBufferDualTileBase`, which lets one array use two tile areas: a tile below `$20` is used as it is, `$20`-`$3F` gets `aTileBase` added, `$40` and up `aTileBaseHigh`.

**The render queue.** `aActiveSpriteOAMQueue` (40 entries of 12 bytes) is for sprites to draw after the active sprites, in order or by Y (`rlFlushActiveSpriteOAMQueueSortedByY`). Only `rlQueueActiveSpriteOAM` fills it and nothing calls that, nor the sorted flush; the queue stays empty.

## Script commands

A script is bytes: a command number (an index into `aActiveSpriteCommandPointers`, 31 entries) and its operands, in the sprite's bank. The commands that show a frame, wait or end the sprite end the step; the others go on to the next command. Use counts are over the source; the map battle's scripts are in its compressed sprite data and are not counted.

| Byte | Macro | Does | Uses |
|---|---|---|---|
| `$00` | `ACTIVE_SPRITE_FRAME d, f` | draw array f for d frames | 293 |
| `$01` | `ACTIVE_SPRITE_END` | free the sprite | 13 |
| `$02` | `ACTIVE_SPRITE_JUMP_WHILE_COUNTER p` | count `aLoopCounter` down; jump while not 0 (no command in the table sets it) | 0 |
| `$03` | `ACTIVE_SPRITE_MAP_BATTLE_FRAME f` | upload frame f of the side's frame tiles | 1 |
| `$04`-`$08` | `..._MAP_BATTLE_STRIKE`, `..._WAIT_STRIKE_TAKEN`, `..._WAIT_STRIKE`, `..._WAIT_STRIKE_DONE`, `..._WAIT_ROUND` | the map battle's strike signals | 0 |
| `$09`, `$0A` | `..._ROUND_SCRIPT`, `..._AUX_ROUND_SCRIPT` | jump to the side's round script | 0 |
| `$0B`, `$0C` | `..._SIDE_SCRIPT`, `..._SIDE_AUX_SCRIPT` | jump to the side's first script | 0 |
| `$0D` | `ACTIVE_SPRITE_END_ROUND` | end the round (`rlMapBattleEndRoundScripts`) | 0 |
| `$0E` | `ACTIVE_SPRITE_TABLE_FRAME d, i` | draw frame i of the frame table at `$7F4598` (`$7F459B` for the other side) for d frames | 97 |
| `$0F` | `ACTIVE_SPRITE_DRAW_MOVING_MAP_SPRITE` | draw the moving map sprite every frame, staying here | 0 |
| `$10`, `$11` | `..._START_MAP_MAGIC`, `..._WAIT_MAP_MAGIC` | start a map magic effect, wait for it | 1, 0 |
| `$12` | `ACTIVE_SPRITE_WAIT n` | wait n frames | 0 |
| `$13` | `ACTIVE_SPRITE_WAIT_WORD n` | the same, but reads a word and skips one byte | 0 |
| `$14` | `ACTIVE_SPRITE_SET_ONCYCLE r` | change the on-cycle routine | 2 |
| `$15` | `ACTIVE_SPRITE_JUMP p` | continue at p | 38 |
| `$16` | `ACTIVE_SPRITE_JUMP_RELATIVE p` | continue at p, within 128 bytes | 2 |
| `$17` | `ACTIVE_SPRITE_CALL r` | call r (same bank) with X = the slot index | 59 |
| `$18` | `ACTIVE_SPRITE_FRAME_RELATIVE d, o` | as `$00`, with o counted from the definition | 0 |
| `$19` | `ACTIVE_SPRITE_MOVE x, y` | add signed bytes to the position | 4 |
| `$1A`-`$1C` | `..._WAIT_BOLT_SIGNAL`, `..._FIRE_BOLT`, `..._WAIT_BOLT_DONE` | the ballista bolt's signals | 0 |
| `$1D` | `ACTIVE_SPRITE_SOUND s` | play sound s, panned by X | 2 |
| `$1E` | `ACTIVE_SPRITE_SET_MUSIC s` | set `wMusicID` | 0 |

Nine more command routines in the bank are in no table and unreachable: a wait that re-reads the previous command, clearing the on-cycle routine, a long call, setting the loop counter, a relative loop, two conditional jumps on a RAM byte or word, writing a word, and an indirect jump by side. With them `$02` would have had a counter to count.

## Limits

| Limit | Where |
|---|---|
| 128 OAM entries; more wrap over the first | `rlPushToOAMBuffer` (`and #$01FF`) |
| 16 active sprites | the create routines (carry set) |
| 17 map unit sprites per 16-line band, less what else is there | `rsUpdateOAMBandSpriteLimits` |
| 40 render queue entries (never used) | `rlQueueActiveSpriteOAM` does not check |

## Open questions

- **Flag `$2000`.** It chooses between two flushes that are the same routine; perhaps the sorted flush once sat behind it.
- **The magic effects' `aBody3`-`aBody6`.** Each effect uses them its own way (a flag its script waits for, palette animation timers, a proc offset), so they have no shared names; per-effect names would need each effect read through.
