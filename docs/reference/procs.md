# Procs

A proc is a small task that runs a little each frame: a fade, a window sliding in, the map battle, a camera scroll, an event's wait. The proc engine keeps 16 of them in parallel arrays, steps each one once a frame from VBlank, and gives each a routine that runs every frame and a script of words that sleeps, calls routines and branches. The code is [engine/core/proc.asm](../../engine/core/proc.asm) (bank `$82`); the definitions and scripts live with the systems that use them. The active sprite, HDMA and IRQ engines follow the same design ([sprites.md](sprites.md), [scanlines.md](scanlines.md)).

Per-routine details: [routines/core.md](routines/core.md) (generated by `tools/reference.py`).

## A definition

A proc is created from a definition in ROM, a `structProcInfo` ([Procs.h](../../include/Procs.h)):

| Offset | Field | |
|---|---|---|
| +0 | name | two characters (`"FI"`, `"Bt"`, `"NO"`); the engine stores it and nothing in it reads it, except the unused `rsPauseMapProcsAndHDMAUnused`, which looks for `"NO"` |
| +2 | init | a routine run once when the proc is created |
| +4 | on-cycle | a routine run every frame |
| +6 | script | the proc's script |

All three are addresses in the definition's bank. The source has 177 definitions. The fade-in proc is a whole example:

```asm
procFadeIn ; 82/8299
  .structProcInfo "FI", rlProcFadeInInit, rlProcFadeInCycle, aProcFadeInCode
aProcFadeInCode ; 82/82B9
  PROC_HALT
```

Its init sets `wScreenFadingFlag`; its on-cycle raises the brightness a step and frees the proc when it is full; its script halts at once, so the on-cycle routine does all the work.

## The proc's RAM

`aProcSystem` holds the engine's state and one array of 16 words per field. A slot's fields are at the same index in every array: the slot number times two. While a proc runs, `wOffset` holds that index, and the engine's routines take it in X.

| Field | Meaning |
|---|---|
| `wFlag` | bit 15 is set while `rlProcEngineMainProcLoop` steps the procs |
| `wOffset` | the running proc's slot × 2 |
| `lPointer` | scratch for the engine's indirect jumps |
| `wInput0`-`wInput3` | arguments for a proc's init routine, set by the creator |
| `aHeaderTypeOffset`, `aHeaderTypeBank` | the definition; an offset of 0 means the slot is free |
| `aHeaderName` | the name |
| `aHeaderBitfield` | the engine's bits (below) and the proc's own |
| `aHeaderOnCycle` | the on-cycle routine (in the definition's bank) |
| `aHeaderCodeOffset` | where the script continues |
| `aHeaderSleepTimer` | frames until the script is read again |
| `aHeaderLoopCounter` | the counter of `PROC_SET_LOOP_COUNTER` and `PROC_JUMP_WHILE_LOOP_COUNTER` |
| `aBody0`-`aBody7` | eight words of the proc's own data |
| `aLastFrameBitfield` | the bitfield as the last frame ended |

**The bitfield.** The engine uses the high bits:

| Bit | Set by | Meaning |
|---|---|---|
| `$0800` | `PROC_SET_ONCYCLE` | the on-cycle routine was changed; nothing tests it |
| `$1000` | only `rsPauseMapProcsAndHDMAUnused`, which nothing calls | the proc is skipped: no on-cycle routine, no script |
| `$2000` | `rlProcEngineFreeProc`, `PROC_END` | the proc has ended |
| `$4000` | `rlProcEngineCreateProc` | created this frame: skipped until the frame ends |

The low bits belong to the proc. Its routines set them and its script tests them with `PROC_JUMP_IF_BITS_UNSET`/`SET`; the scripts use `$0001`, `$0002` and `$0004`.

## Creating and freeing

`rlProcEngineCreateProc` takes a long pointer to a definition in `lR44`:

1. It looks for a free slot from 15 down to 0. While the engine is stepping (`wFlag` bit 15), it skips the slot being stepped even if that proc has just ended. With every slot taken it returns carry set and nothing is created; there is no other limit.
2. It fills the slot: the definition, the name, the on-cycle routine and script from the definition, a sleep timer of 1, and 0 in the bitfield, the loop counter and `aBody0`-`aBody7`.
3. It runs the init routine with X = the slot index and the data bank set to the definition's bank. The init reads `wInput0`-`wInput3` if it needs arguments.
4. It gives the proc one step at once (the on-cycle routine, then the script, since the timer counts down to 0) and sets bit `$4000`.
5. It returns carry clear with A = the slot index.

Other calls:

| Routine | Does |
|---|---|
| `rlProcEngineCreateProcByIndex` | creates in slot A; carry set if it is taken |
| `rlProcEngineFindProc` | finds a proc made from the definition at `lR44`; carry set and X = its slot index |
| `rlProcEngineFreeProc` | frees slot X / 2: clears the definition, sets `$2000` |
| `rlProcEngineFreeProcByIndex` | frees slot A; carry set if it was free |
| `rlProcEngineCheckProcEnded` | A = a slot index: carry set if `$2000` is set in `aLastFrameBitfield` |
| `rlProcEngineResetProcEngine` | zeroes `aProcSystem` (the engine's init routine) |

A freed slot keeps `$2000` in its bitfield until another proc takes it, so `rlProcEngineCheckProcEnded` answers "has the proc that was in this slot ended", as long as nothing has reused the slot. The map battle uses it to wait for its Pavise proc and the scripted critical's effect, the village raid and the Belhalla mages for the procs they start.

## The frame step

The proc engine is the first of the per-frame engines ([game_states.md](game_states.md)). `rlProcEngineMainProcLoop` sets `wFlag` bit 15 and steps every live slot from 15 down to 0 (`rsProcEngineRunProcOnCycleAndCode`):

1. Set the data bank to the proc's bank.
2. Skip the proc if bit `$1000` or bit `$4000` is set.
3. Call the on-cycle routine.
4. Count the sleep timer down. If it is not 0, the step is over.
5. Read the script from `aHeaderCodeOffset`, one word at a time:
   - a word from `$8000` up is the address of a command routine in bank `$82`, followed by its operands; the command runs and the reading goes on, unless the command ends the step;
   - a word below `$8000` is a sleep: it becomes the sleep timer, the offset moves past it, and the step is over.

After the last slot, `rsProcEngineUnblockAllProcs` clears bit `$4000` everywhere and copies each bitfield to `aLastFrameBitfield`.

So a proc's on-cycle routine runs every frame, and its script runs on the frames its sleeps allow. `PROC_YIELD n` makes the script wait n frames; `PROC_YIELD 0` sets the timer to 0, which the next count wraps to `$FFFF`: a sleep of 65,536 frames. A proc created by another proc during the step runs its first step at creation and is skipped by the loop until the next frame; one created in a slot the loop has already passed is not stepped twice.

## Script commands

The macros are in [Procs.h](../../include/Procs.h); the uses are counted over the source.

| Macro | Operands | Does | Uses |
|---|---|---|---|
| `PROC_YIELD n` | | sleep n frames and end the step | 375 |
| `PROC_END` | | free the proc and end the step | 21 |
| `PROC_HALT` | | stay on this command and end the step; the timer stays at 0, so the script is not read again for 65,536 frames and only the on-cycle routine runs | 88 |
| `PROC_HALT_SLEEP` | | as `PROC_HALT` with a sleep of 1, so the halt is read again each frame | 0 |
| `PROC_CALL r` | long routine | call it (X = the slot index) | 309 |
| `PROC_CALL_ARGS r, n` | long routine, count, n bytes | call it with Y at the arguments, then skip them | 60 |
| `PROC_SET_ONCYCLE r` | routine | change the on-cycle routine; sets `$0800` | 52 |
| `PROC_JUMP p` | position | continue at p | 14 |
| `PROC_SET_LOOP_COUNTER n` | word | set `aHeaderLoopCounter` | 11 |
| `PROC_JUMP_WHILE_LOOP_COUNTER p` | position | count down; jump to p while not 0 | 11 |
| `PROC_JUMP_IF_BITS_UNSET p, b` | position, bits | jump to p if none of b is set in the bitfield | 116 |
| `PROC_JUMP_IF_BITS_SET p, b` | position, bits | jump to p if any of b is set | 4 |
| `PROC_CREATE_ACTIVE_SPRITE d, x, y` | long definition, X, Y | create an active sprite at (x, y) | 0 |

A halted proc leaves its script only if its on-cycle routine changes `aHeaderCodeOffset` or frees the proc. Procs end themselves far more often from a routine (`rlProcEngineFreeProc`, 69 calls) than with `PROC_END` (21).

**Waiting on a bit.** A script that has to wait for something its routines will notice loops on a bit:

```asm
_9C3C
  PROC_YIELD 1
  PROC_JUMP_IF_BITS_UNSET _9C3C, $0002
```

Meanwhile the on-cycle routines move on by themselves ([map_action_animations.asm](../../engine/battle/map_action_animations.asm)): `rlProcVillageRaidWaitRoundStart` waits for the round to start and installs `rlProcVillageRaidRunRound`, which sets bit `$0002` when the round has stopped running; the script then goes on. The map battle and the map actions are built from such waits.

## Event procs

Event scripts start procs (fades, scrolls, the map battle) and wait for them. They use the same 16 slots. `rlEventEngineCreateProc` creates the proc with `rlProcEngineCreateProc` and records its definition under the slot's index in `wEventProcOffsets` and `wEventProcBanks` (`$FFFF` in the bank word when the slot is not an event's), and sets bit `$0004` of `wEventEngineFlags`.

While that bit is set the event engine polls (`rsEventEnginePollBlockingProcs`): a recorded slot that no longer holds the same definition has ended, and its record is cleared. When no recorded proc is alive it sets bit `$0002`, and the script goes on. A proc marked with `$0200` in its bank word (`rlEventEngineMarkProcNonBlocking`) does not hold the script. `rlEventEngineFreeAllProcs` frees every recorded proc, at the start and end of a script. [events.md](events.md) has the commands that start them.

## Open questions

- **The name.** The two-letter name is copied into `aHeaderName` and never compared, except by `rsPauseMapProcsAndHDMAUnused` (`"NO"`). Whatever used names (a debugger?) is not in the ROM.
- **Bit `$0800`.** `PROC_SET_ONCYCLE` sets it and nothing reads it.
