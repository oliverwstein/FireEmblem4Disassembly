# Events

Chapter events, scripted scenes, and the two interpreters that drive them: the **event condition engine** (which watches for triggers such as turn starts, battles, talks, villages, and seizures) and the **event script engine** (which runs cutscenes, dialogue, camera scrolls, unit spawns, and ASMCs). Per-routine details: [routines/events.md](routines/events.md) (generated by `tools/reference.py`).

## Chapter event RAM and flags

- `rlStartChapterEvents` looks up the chapter's entry in `aChapterEventPointers` and calls `rlBeginChapterEvents`, which appends an entry to `aChapterEventRAMData` (`structChapterEventRAMEntry`) and starts the chapter's opening event.
- `rlRefreshChapterEventPointers` updates `EventPointer` for every entry in `aChapterEventRAMData` from `aChapterEventPointers` (used when loading a save or returning to the map).
- Event flags are stored as permanent flags (`include/PermanentFlags.h`) and per-chapter flags inside `aChapterEventRAMData`, tested and updated by `rlCheckEventFlagSet`, `rlSetEventFlag`, and `rlUnsetEventFlag`.
- Active map tile changes are tracked as bits in `aChapterActiveMapChanges` (`rlCheckMapChangeActive`), cleared on generation change (`rlClearChapterActiveMapChanges`), and re-applied when reloading the map display (`rlApplyAllActiveMapChanges`).

## Event conditions

When a gameplay action occurs (turn start, battle, talk, visit, seize, area entry, arena exit, etc.), the caller sets `bEventActionIdentifier` and `wEventEngineArgument1`–`4`, then calls `rlGetAndRunChapterMapEventConditions` (or `rlRunChapterMapEventConditions`):

1. `rlRunChapterEventConditions` loops over the condition list until `$FFFF`, dispatching each command byte through `aChapterEventConditionCommands` (`rsRunEventConditionCommand`).
2. Most conditions funnel into `rsEvaluateEventCondition`, which checks `bEventActionIdentifier` against the expected action, tests (and optionally sets/clears) the condition's event flag (`$FF` = always), and calls `(lEventPointer)` to test the condition's parameters (including Gen 2 child/substitute ID unification via `rsEventUnifyGen2CharacterIds`).
3. When a condition matches, its body runs; otherwise `rsTrySkipEventConditionCommand` or `rsEventFindConditionBreak` / `rsEventFindTurnCheckBreak` skips to the matching break marker (`$20`/`$6666` or `$25`/`$6666`).

## Event script interpreter

1. `rlEventEngineBeginScript` increments `wEventEngineState`, clears event menu windows and moving map sprites (`rlClearMovingMapSpritesAndSound`), frees old event procs, and jumps into `rlRunEventCommand`.
2. `rlRunEventCommand` first calls `rsEventEngineCheckProcsDone`, which polls `wEventProcBanks`/`wEventProcOffsets` (`rsEventEnginePollBlockingProcs`). Any proc started via `rlEventEngineCreateProc` blocks the script until it frees itself (`rlEventEngineFreeProc`), unless marked non-blocking (`$0200` via `rlEventEngineMarkProcNonBlocking`, e.g., `rlASMCContinueDuringDialogue`, `procEventCyclePalette`, or `procDemoSkipFadeOut`).
3. Once no blocking procs remain, `rlRunEventCommand` reads commands from `[lR22]` (`lActiveEventPointer` + `wActiveEventOffset`), advancing or yielding (`$FD` / `$FEFE`) until the script finishes (`wEventEngineState = 2`).
4. Unit movement and spawning commands (`MOVE_TEMPORARY_*`, `LOAD_UNIT_*`) dispatch through `aEventUnitMoveHandlers` (`rsDispatchEventUnitMoveHandler`), queue sprite decompression, assign map-sprite movement sound channels (`rlAssignMovingSpriteSoundChannel`, `rlStartMovingSpriteSound`), and can be waited on with `WAIT_UNTIL_MAP_SPRITES_HALTING` (`procEventWaitMapSpritesHalting`).

## Returning to the map and IRQ engine

- `rsReturnToMapMainLoop` (installed as `wMainLoopPointer` by menus, battle scenes, epilogue, and event command `$3B` with `procEventWaitFadeToMap`) resets screen registers, BG2/BG3 tilemaps, OAM, sprites, HDMA, and IRQ, reloads the chapter map display (`rsSetupMapDisplayByGameMode` / `rsReloadChapterMapDisplay`), restores map menus and music (`rsResumeMapAfterMenu`), and resumes `GAMESTATE_MAP_STEP`.
- The HV IRQ engine (`rlEnableIRQEngine`, `rlIRQEngineCreateEntry`, `rlIRQEngineSyncAndSort`, `rsIRQEngineSortEntries`, `rsIRQEngineProgramNextEntry`) lives in bank `$82` inside [event_scripts.asm](../../engine/events/event_scripts.asm) and is shared with the title screen, battle scene, world map, and map loop.

## Dependencies

- **Map & menus:** `procItemPopUp`, `rsReturnToMapMainLoop`, `rlRunMapMenuUploadIfEnabled`, `rsUploadDirtyMapMenuRows`, map scroll (`procMapScroll`, `rlStepEventMapScroll`), and map tile changes (`rlApplyMapTileChange`).
- **Map battle & magic effects:** `procEventBerserkCast` / `procEventBerserkMagicEffect` (uses Berserk effect `$27`), `procBelhallaMagesAttack` / `procBelhallaMagesBlast` (uses Meteor effect `4`), and `rlSetupScriptedBattleActionStruct`.
- **Dialogue & world map:** `rlInitWorldMapDialogueSlot` / `rlWorldMapDialogueHDMA` (BG3 overlay dialogue used by events and `world_map_test.asm`), plus `procEventWaitDialogueEnd` and `procEventDialogueWithBG`.
