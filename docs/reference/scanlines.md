# Scanline effects: HDMA and IRQ

Two engines change the picture partway down the screen. The HDMA engine runs up to eight HDMA channels, each writing a table of values to a PPU register line by line; each channel is an entry with a script that swaps tables over time. The IRQ engine keeps up to seven mid-frame interrupts, sorted by scanline, each calling a routine at its line and stepping a script that can move it. Both follow the proc engine's design ([procs.md](procs.md)): parallel arrays, an init and an on-cycle routine, a script of words. The code is in `engine/core/display/` (bank `$82`).

Per-routine details: [routines/core.md](routines/core.md) (generated by `tools/reference.py`).

## The HDMA engine

**Entries and channels.** `aHDMASystem` has eight entries; entry n runs on DMA channel n. Each field is an array of eight words indexed by entry × 2:

| Field | Meaning |
|---|---|
| `aTypeOffset`, `aTypeBank` | the definition; 0 means free |
| `aBitfield` | `$0800` on-cycle changed, `$1000` skip the entry, `$2000` ended; the low bits are the entry's own |
| `aOnCycle`, `aCodeOffset`, `aSleepTimer` | as for procs |
| `aTimer` | the loop counter |
| `aOffset` | the table the channel reads (in `bBank`) |
| `aBankAndBBADx` | the table's bank and the B-bus register |
| `aDMAPxAndIndirectBank` | `DMAP` (the transfer mode, direct or indirect) and the bank of an indirect table's data |

**A definition** ([HDMA.h](../../include/HDMA.h)) is the three routines of a proc (init, on-cycle, script), then the table (long), the register, `DMAP`, and for an indirect entry the data bank.

**Creating.** `rlHDMAEngineCreateEntry` takes the definition in `lR44` and uses the lowest free entry; `rlHDMAEngineCreateEntryByIndex` uses entry `wR40`. Both return carry set if they cannot. The init routine runs with X = the entry × 2 and `wR41` = the entry × 16, its channel's register offset. `rlHDMAEngineFreeEntryByIndex` and `rlHDMAEngineFreeEntryByOffset` free one; `rlResetHDMAEngine`, the engine's init routine, clears them all, turns HDMA off and resets the eight channels' registers.

**The frame.** The HDMA engine is the third per-frame engine ([game_states.md](game_states.md)). `rlHDMAEngineMainLoop` steps entries 0 to 7 (`rsHDMAEngineRunOnCycleAndCode`):

1. the entry's channel is marked live, even if the entry is skipped;
2. bit `$1000` skips the rest (only the unreferenced `rsPauseMapProcsAndHDMAUnused` sets it);
3. the on-cycle routine runs and the sleep timer counts down; at 0 the script runs.

It leaves the live channels in `bHDMAPendingChannels`.

**The hand-off.** The next VBlank routine calls `rlHandlePossibleHDMA` after the DMA queue: it starts the channels in `bDMAPendingChannels`, then for each live channel writes the entry's table address, register, `DMAP` and indirect bank to the channel's registers (`rlHDMAArrayEngineProcessHDMAArray`) and enables them in `HDMAEN`. A VBlank routine that does not call it has no HDMA; `rsDefaultVBlankRoutine` does not. The table address is written to the channel every VBlank, so an on-cycle routine switches tables by changing `aOffset`. Since `rlProcessDMAStructArray` turns off `HDMAEN` and uses channel 1 (and `rlDMAPaletteAndOAMBuffer` channels 0 and 1), the DMA queue has to run before the hand-off, as it does in every VBlank routine that has both.

**The script.** A word from `$8000` up is a command; any other word starts an `HDMA_YIELD`: a frame count and the table to use for those frames. A script of yields is an animation of tables.

| Macro | Does | Uses |
|---|---|---|
| `HDMA_YIELD n, t` | use table t for n frames | 2 |
| `HDMA_SLEEP n` | keep the table for n frames | 1 |
| `HDMA_END` | free the entry (`$2000`) | 1 |
| `HDMA_HALT` | stay here; only the on-cycle routine runs | 36 |
| `HDMA_HALT_SLEEP` | the same, re-read each frame | 0 |
| `HDMA_CALL r` | call a long routine | 0 |
| `HDMA_SET_ONCYCLE r` | change the on-cycle routine (`$0800`) | 0 |
| `HDMA_JUMP p` | continue at p | 1 |
| `HDMA_SET_TIMER n`, `HDMA_JUMP_WHILE_TIMER p` | a counted loop on `aTimer` | 0 |
| `HDMA_JUMP_IF_BITS_UNSET p, b`, `HDMA_JUMP_IF_BITS_SET p, b` | branch on the entry's bits | 1, 0 |
| `HDMA_SET_TABLE_BANK b` | set the table's bank | 1 |

Most entries halt at once (`HDMA_HALT` is used 36 times, every other command once or not at all) and do their work in the on-cycle routine, rewriting their tables in RAM each frame. About 70 places create entries; the battle scene's effects (`effects.asm`, `screen.asm`, `hud.asm`, `script.asm`), the opening credits, the title, the windows and menus, the dialogue box, the phase banner and the castle's shops are the main users.

**Double-buffered tables.** A table built during a frame is read during the next, since the channel is programmed at the start of VBlank. The dialogue box's unfolding and folding entries (`aDialogueBoxUnfoldingHDMA`, `aDialogueBoxFoldingHDMA`, indirect, on `BG2VOFS`) rebuild their table each frame into one of two copies, `aDialogueBoxHDMAIndirectTableEven` or `...Odd` by bit 0 of `wVBlankEnabledFramecount`, and point `aOffset` at it (`rsDialogueBoxHDMABuildTables`); the unfolding counts `wDialogueBoxHDMACycleCounter` 0-7, the folding 6-0, then each sets `wDialogueBoxHDMAStatus` to `$FFFF`.

**Direct tables.** `rlBuildHDMADirectTableEntries` writes the 3-byte entries of a direct table (a line count and a word) at `lR18`. A run of `$7F` lines or more is split into `$78` lines and the rest, since a count of `$80` or more means repeat mode.

## The IRQ engine

**Entries.** `aIRQSystem` has seven entries in arrays of eight words; the eighth is the scratch space for swaps.

| Field | Meaning |
|---|---|
| `wFlag` | `$8000`: the engine is off |
| `wOffset` | the entry whose IRQ comes next, × 2 |
| `wCount` | live entries, 0-7 |
| `wSortedCount` | `wCount` when the entries were last sorted |
| `lRoutine` | the routine the next IRQ calls, and its bank |
| `aTypeOffset`, `aTypeBank` | the definition; its bank is the routine's and the script's |
| `aHTime`, `aVTime` | where the IRQ fires: written to `HTIME` and `VTIME` |
| `aRoutine` | the routine called at the IRQ |
| `aCodeOffset`, `aSleepTimer` | the script |
| `aBitfield` | tested by the script's bit jumps; nothing sets it |

**A definition** is four words in its bank: H time, V time, routine, script. For example the battle scene's five ([screen.asm](../../engine/battle_scene/screen.asm)) all fire at H `$60`, on lines `$0E`, `$7E`, `$9C`, `$A1` and `$CF`.

**Creating and running.** `rlIRQEngineCreateEntry` (definition in `lR44`) puts the entry at index `wCount`; it returns carry set when seven are in use. `rlEnableIRQEngine` turns on the H and V timer IRQs (`bBufferNMITIMEN` `$30`), clears the off bit, sorts and programs the first entry (`rlIRQEngineSyncAndSort`) and installs `rsIRQEngineCycle` in `wIRQPointer`. `rlDisableIRQEngine` undoes that and puts `rsDefaultIRQRoutine` back. `rlResetIRQEngine`, the engine's init routine, clears everything and turns it off. Screen openers reset it; the chapter map installs one entry (`aMapRowUploadIRQ`, line `$D7`, which uploads a streamed map row and column), the world map and the title screen two each, the battle scene five.

The engine's per-frame routine in `aTaskTable` does nothing (`rlIRQEngineStub`). Its work runs from the IRQ:

1. `rlIRQ` sees the timer IRQ and calls `rsIRQEngineCycle`, which calls `rlRunIRQEngine`;
2. unless the engine is off, it calls the current entry's routine (data bank = the entry's bank);
3. it steps that entry's script (`rsIRQEngineStepSlotCode`): the sleep timer counts down once per IRQ, and at 0 the script runs;
4. it moves to the next entry down, wrapping from 0 to the topmost, and writes that entry's H and V times and routine (`rsIRQEngineProgramNextEntry`).

**The order.** `rsIRQEngineSortEntries` orders the entries by V time, highest first, so index `wCount - 1` is the top of the screen and the IRQs walk down the indexes. It runs only when `wCount` has changed since the last sort (`rlIRQEngineSyncAndSort`, called by `rlEnableIRQEngine`, and every frame by `rsMapVBlank`, `rsRunBattleSceneVBlank` and `rsRunTitleScreenVBlank`). The sort makes one compare-and-swap pass at each gap from half the count down to 1. That does not order every arrangement: two of the six orders of three entries come out unsorted (including strictly ascending `(1, 2, 3)`), and 44 of 120 five-entry orders fail. Every set the game creates — including the battle scene's `$0E`, `$CF`, `$7E`, `$9C`, `$A1` — happens to sort cleanly to descending order.

**The users.** Every IRQ script in the game is a single `rsIRQCodeHalt`; the entries differ only in line and routine. The map's `aMapRowUploadIRQ` (H `$68`, line `$D7`, `rlIRQUploadMapRowAndColumn`). The world map's `aWorldMapTopIRQInfo`/`aWorldMapBottomIRQInfo` and the title screen's `aTitleScreenTopIRQ`/`BottomIRQ`. The battle scene's five, at H `$60`: line `$0E` writes `bBattleSceneScreenINIDISP` (the scene's step writes `INIDISP` 0 every frame, so the lines above are black), line `$CF` forces blank and turns off HDMA, and lines `$7E`, `$9C` and `$A1` switch the layers, tilemap and tile bases, scroll offsets, windows and color math for the HUD by `bBattleSceneBG3Mode`. Each battle scene handler waits for HBlank (`HVBJOY` bit 6) before writing.

**The script.** A word from `$8000` up is a command (`rsIRQCode*`); any other word is a count of IRQs to sleep, followed by a new V time for the entry. So a script can move its interrupt from frame to frame; a moved entry is re-sorted only when the count changes.

| Command | Does |
|---|---|
| `rsIRQCodeSleep` | sleep n IRQs, keeping the line |
| `rsIRQCodeEnd` | free the entry: its V time becomes 0 and the sort moves it to the end, where the decremented count drops it |
| `rsIRQCodeHalt`, `rsIRQCodeHaltSleep` | stay here; the routine keeps running at its line |
| `rsIRQCodeCall` | call a long routine |
| `rsIRQCodeSetRoutine` | change the entry's routine |
| `rsIRQCodeJump`, `rsIRQCodeJumpIfBitsUnset`, `rsIRQCodeJumpIfBitsSet` | branch |

Nothing uses `rsIRQCodeCall` or the four after it. The IRQ scripts have no macros yet.

**The third routine.** `aIRQEngineMainActionTable`'s third word is `rlIRQEngineRestoreDefaultIRQ` (restore the default IRQ routine, `sei`). Only `rlFindAndJumpTaskTableUnused` reads that word, and nothing calls it ([game_states.md](game_states.md)).

## Limits

| Limit | Where |
|---|---|
| 8 HDMA entries, one per channel | `rlHDMAEngineCreateEntry` (carry set) |
| 7 IRQ entries | `rlIRQEngineCreateEntry` (carry set) |
| A direct HDMA run of at most `$78` lines from `rlBuildHDMADirectTableEntries` | `rlBuildHDMADirectTableEntries` |
