# The core

The core is the part of the program that decides what runs and when, and the library everything else uses. It is `engine/core/`, about 17,900 lines in five groups. This page is the overview; each mechanism has its own page.

`options.asm` (at the top of `engine/core/`) holds the getters and setters of `wOptionSettings`: battle animations, the unit and terrain windows, text and enemy speed, sound, auto-save and auto cursor. Per-routine details for all of it: [routines/core.md](routines/core.md) (generated by `tools/reference.py`).

## The shape of the program

There is no operating system. After reset the program runs two threads of control:

1. **The main loop** (`rlMainLoop`) runs in the time between frames. It calls the routine at `wMainLoopPointer` and then waits for the next VBlank to finish. Most screens' routine is `rsRunFrameTasks` (the soft reset check, the decompression queue, deferred sound); the map's adds the AI. Installing another routine changes screens: the new routine is the next screen's opener, which runs once and sets everything up.
2. **The VBlank interrupt** (`rlVBlank`) runs 60 times a second and calls the routine at `wVBlankPointer`. Each screen's VBlank routine first sends the frame's queued changes to the hardware (the DMA queue, the palette and sprite buffers, the PPU register buffers), then reads the joypads, then runs the game logic: the **game state routines** (`wGameStateRoutine1`, then `wGameStateRoutine2`), then the **per-frame engines** in `aTaskTable` (procs, active sprites, HDMA, the IRQ engine, events), then sound. If the logic overruns the frame, the next VBlank only sends sound and counts a lag frame.

A third pointer, `wIRQPointer`, runs at mid-frame interrupts; the IRQ engine uses it to change registers partway down the screen.

So almost all of the game's logic runs inside the interrupt, after the hardware has been updated for the frame; the main loop does the slow work (decompression, the AI) that can spread over frames.

## Boot, in one paragraph

`rlReset` scans RAM for signs of a copier and checks its own code's checksums, then `rlColdResetClearMemory` clears RAM and VRAM, uploads the sound driver and installs `rlInitEngineAndStartLogo` as the main loop routine. That routine registers the five engines and opens the opening logo, whose setup seeds the random numbers and loads the options ([frame.md](frame.md)).

## Depends on

Nothing above it. The core calls the sound driver ([engine/sound/](../../engine/sound/)), the event engine's per-frame routine, and every screen's openers and game state routines.
