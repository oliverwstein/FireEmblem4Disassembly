## How chapters are written

- Start from the reference page, then check every claim the chapter makes against the code. Outlines and reviews have been wrong too: the outline promised "gates", and a review proposed a 24-sprite cap the code doesn't have.
- A complete code path is the answer; don't contradict it from memory of how the game plays. Raise an emulator question only when the code leaves the outcome open.
- Plain prose: no strawman contrasts with "most games", no "not X but Y" reframes, no closing flourishes. Open each chapter and section on the system (its elements, rules, and how the engine organizes them), not an in-game vignette; ground it in concrete rules and data after that, and end sections on a fact (STYLE.md). Check each chapter for these before handing it over.
- Fix wrong names, comments and doc claims found while writing (source changes byte-identical, separate commit), and log each in "Mistakes found in earlier work". Retail-ROM bugs go in their own table.

Quirks that aren't bugs, recorded so they aren't rediscovered:

- Battle experience comes from the last connecting hit: each hit overwrites `GainedExperience` instead of adding to it; non-lethal arena hits earn none (Ch. 6, 7).
- Promotion level is read from the target class; Myrmidon, Archer, Pegasus Rider and Dragonrider store `PromotionLevel = 1`, which nothing reads (Ch. 7).
- Tyrfing starts broken: `rlInitiateItemRAMData` sets `PI_Tyrfing`'s durability to 0, and Byron hands it over that way (Ch. 3).
- Only 140 of the item table's 256 slots are ever used; nothing creates item records after a new game (`rlAppendItemsFromList` has no callers) (Ch. 3).
- Promotion never raises a player unit's max HP: HP has no class term (Ch. 2).
- Castle income is (allied castles − 2) × 1,000 per living unit, counted against the player whatever army is paid (Ch. 4).
- Location bit `$40` is set on a seize and never read; `rlCheckLocationState40` has no callers (Ch. 5).
- `aInventoryRAMArea` has 73 slots (declared 72 + 1); nothing in the code explains the extra one (Ch. 1).
- Location types 1 and 3–6 exist in the type table, but no chapter uses them (Ch. 5).
- The unit menu's もちもの (items) never appears: it needs an item whose staff effect has a target, and every non-staff item has `StaffEffect None`; the use/discard menu behind it is unreachable (Ch. 10).
- Only Seliph can dismount: `UnitSkill1Dismount` is set only by `rsOverwriteSeliphUnitData` at the generation change, and only `KnightLord` has `ClassSkillDismount` (Ch. 10).
- Only Sigurd and Seliph can seize: the check compares the class with `KnightLord` and `JuniorLord` (Ch. 10).
- An action condition's flag is set before its body runs, so a once-only condition whose `EVENT` can't start (another script running) never matches again; `EVENT`'s own flag stays clear on failure and retries (Ch. 11).
- The chapter event pool has room for three chapters and the flag lookups take a chapter number, but only the current chapter's entry can be read; other chapters' flags read as clear (Ch. 11).
- Scripts can't be skipped: openings mark a skip point (`SKIP_POINT`) and `rsGetEventLength` records it, but the routine that would jump there on Start (`rsCheckSkipActiveEventUnused`) has no caller (Ch. 12).
- `LOAD_UNIT_BY_GROUP`'s sprite color parameter is read and then overwritten with the unit's allegiance color (Ch. 12).
- `TEST_FLAG_IN_CHAPTER_SET` for a chapter other than the current one leaves the truth flag as the last test left it (Ch. 12).
- 37 of the 93 script commands are never used; the only relative jump is in the pre-combat dialogue template copied to RAM (Ch. 12).
- Message speed settings 0-4 give 6, 5, 4, 3 and 1 frames per character (6 − setting, with 2 replaced by 1); keepers always talk at 2 and the epilogue at 6 (Ch. 13).
- The dialogue insert stack holds six pointers; a seventh insert (name, number, piece) is skipped without notice. Dialogue command numbers `$41`-`$7F` hang in an endless loop. Sixteen dialogue commands appear in no text (Ch. 13).
- The menu font has 15 kanji (剣庫回城兵大書杖国軍帝系特効部); menu strings are Shift-JIS and any other character draws blank (Ch. 13).
- Map dialogue slots draw at VRAM `$8000`/`$9000` over the menu font and icons, so `procDialogue` decompresses them again after every map conversation (Ch. 13).
- The AI's target scoring by class priority, effectiveness and triangle (`rsAIScoreTargetsNearLeader`, `aAIClassTargetPriorityTable`) sits after an unconditional branch and never runs; `aAIClassWeightTable` has no reader at all (Ch. 14).
- Neither AI list checks its count: 24 group members, 48 targets; a 49th target would overwrite `aPermanentEventFlags` (Ch. 14).
- Seven AI script commands are unused, among them `AI_TARGET_VILLAGE` and the three copies of the surround command `$1A`-`$1C` (Ch. 14).
- Every item shop sells one pooled stock and every secondhand shop offers everything sold anywhere: shop and pawnbroker records have an owning castle that no list reads (`rlBuildStockList`). One castle per chapter has a shop list; the stock accumulates until Chapter 6 reverts it (Ch. 15).
- Every return to the town (after each facility) announces event action 6 again (`rlCastleOpenTown`) (Ch. 15).
- Class change sets the list item state to 3, which no item has; its list is always empty. Class change is refused in Chapter 6, whose castles also lack the arena (Ch. 15).
- A dance inside the castle refreshes every unit in the dancer's castle (`rsActionStructDance`, castle bit) (Ch. 15).
- Arena fights don't end the unit's action, and arena wins and losses aren't recorded; a fallen player unit keeps 1 HP (Ch. 16).
- After a yield, changing weapons changes the fight's distance and the opponent window's lookup, but not the opponent already built at `$2100`: Chapter 1's level-3 Shark can be fought with a bow at two tiles, where he can't reach (Ch. 16).
- A weapon that breaks in the arena keeps swinging for the rest of the fight: `rsCheckForWeaponInventorySlot` only rejects an empty slot there (Ch. 6, 16).
- No condition list uses a flag byte with bit 7 ("must be set, cleared on match"), opcodes `$22`-`$24`, or any `CHILD` condition other than `CHECK_CHILD_TALK` (Ch. 11).
- The random number table starts the same at every power-on: its only seeding is at boot, before any frame is counted (seed 0). Saves carry the table and its position, so a loaded save rolls the same sequence each time (allocation.md).
- The IRQ engine's sort makes one pass per gap and does not order every set (two of the six orders of three entries); every set the game creates comes out right (scanlines.md).
- A RAM area that runs out tints the screen and hits `BRK`: the handles and compaction that could make room are never used (`rlAllocateRAMAreaWithHandle` has no callers) (allocation.md).
- The decompression queue holds five entries; the fifth's end marker shares a byte with `bFrameCounterByOnes`. The DMA queue has no overflow check either (graphics.md, frame.md).
- The sprite buffer wraps after 128 sprites; exactly 128 leaves the offset at 0 and `rlHideSprites` hides them all (sprites.md).
- Dead paths in the engines: the active sprite render queue (never filled), flag `$2000` (two identical flushes), nine command routines outside the table and the loop counter none of them sets; `rlSetMainLoopPointer`'s `wR26` redirect and the dispatcher's bank-`$7D` rule; proc bit `$1000`; the IRQ script commands after `Halt` (frame.md, game_states.md, procs.md, sprites.md, scanlines.md).
